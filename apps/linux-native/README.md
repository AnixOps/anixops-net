# AnixOps Net for Linux (native)

The Linux client written with GTK 4, libadwaita and Rust (`docs/architecture/desktop-native.md`). It runs as
the signed-in user; the engine runs in the daemon (`apps/linux-daemon`), which the window reaches over the
daemon's socket. So far: the window, the sidebar with the six pages, light and dark, three languages, and the
link to the daemon, whose state the foot of the sidebar shows, and the first real page: the overview
(connect and disconnect, the node in use, speed and traffic). The other pages come next.

- `src/sections.rs`, `src/launch.rs`: what the window shows and how it is started, without GTK. Built and
  tested on every system by the workspace jobs. A test checks that the pages are the ones the Windows window
  has.
- `src/overview.rs`: the overview page without GTK: turning the daemon's answer into the page's sentences,
  numbers and whether the button can be pressed. What the daemon's state means is decided by the daemon (its
  `overview` command, asked once a second), the same answer the Windows window gets.
- `src/overview_page.rs`: the overview page's widgets.
- `src/connections.rs`: the open connections without GTK: the daemon's `connections` answer (where each one
  goes, by which rule and route, what it moved, the ones a search leaves) turned into the list's rows, count
  and sentences, and what closing one or all of them asks of the daemon.
- `src/connection_list.rs`: the list's widgets, a dialog over the overview page opened with the button on
  the row that counts the open connections. It is asked for once a second while it is shown.
- `src/proxies.rs`: the proxies page without GTK: the daemon's `proxies` answer (the nodes a search leaves,
  split by subscription, each with its last delay test) turned into the list's rows and the page's
  sentences, and what the page asks of the daemon (import, test, use a node).
- `src/proxies_page.rs`: the proxies page's widgets. The node list is a `GtkListView` with the subscriptions
  as section headings; the selected row is the node in use.
- `src/subscriptions.rs`: the list of subscriptions without GTK: the daemon's `subscriptions` answer turned
  into one row per subscription (name, node count, last update, use, expiry, why the last update did not
  work), and what a row asks of the daemon (update, rename, remove).
- `src/subscription_list.rs`: the list's widgets, a dialog over the proxies page opened with the page's
  "Subscriptions" button. Renaming and removing ask first; "remove" is never the answer Enter gives.
- `src/groups.rs`: the policy groups without GTK: the daemon's `groups` answer turned into one row per group
  (name, how it chooses, the member in use), and what choosing a member asks of the daemon.
- `src/group_list.rs`: the groups' widgets, a dialog over the proxies page opened with the page's "Policy
  groups" button, which is only there when the subscription in use has groups. A group the user chooses in
  opens a second page with its members; the selected one is the member in use.
- `src/node.rs`: one node's details without GTK: the daemon's `node_details` answer (name, protocol, server,
  port, whether it can be changed or removed, share link and QR code) turned into what the dialog shows, and
  what saving and removing ask of the daemon. Whether what was typed can be saved is the daemon's answer too
  (`check_node`).
- `src/node_dialog.rs`: the dialog's widgets, opened with the button at the end of a node's row: three boxes,
  "save" and "remove" (asked first; Enter answers "cancel"), the share link, its QR code and "copy link".
- `src/window.rs`: the window (relm4 over gtk4-rs and libadwaita). Only built with the `gui` feature, on Linux,
  because it needs the GTK 4 and libadwaita development files. It links `crates/client-window` (the standing
  link to the daemon and the answers to what the daemon asks of the user's session) and none of the engine.
- `data/brand-light.css`, `data/brand-dark.css`: the brand's accent over libadwaita's colours, generated by
  `.github/scripts/design_tokens.py` and never edited by hand. High contrast keeps the system's colours.
- The wording is `crates/client-strings/catalogue.json`, the same file the Windows window builds in.

It needs GTK 4.14 and libadwaita 1.5 or later (Ubuntu 24.04, Debian 13, Fedora 40).

Options for tests and screenshots: `--language zh|zh-Hant|en`, `--theme light|dark`, `--page <id>`,
`--size <width>x<height>`, `--socket <path>` (where the daemon listens, instead of
`/run/anixops-net/core.sock`), `--show subscriptions|groups|node|connections` (open the list of subscriptions, the policy groups, the first
node's details or the open connections), and
`--screenshot <file.png>`, which draws the window into the file with the
window's own renderer and quits.

The "Linux native app" job in CI builds and lints the window, draws every page in every language and theme
(`.github/scripts/linux-native-screenshots.sh`, uploaded as an artifact) and operates the running window
through AT-SPI the way a screen reader does (`.github/scripts/linux-native-a11y.py`). The same script then
runs the window against the real `anixops-netd`: not running, found, connected and disconnected with the
overview's button, the open connections (two connections held open through the engine are listed, searched,
closed one by one and all at once), the proxies page (import, search, choosing a node, delay test), a node's details (shown,
a port of 0 refused, another name, server and port saved, removed after asking), the list of subscriptions
(a subscription served by the script itself is listed with its use and expiry, updated, renamed and removed),
the policy groups (a subscription with rules and groups is imported, its groups are listed and a member is chosen),
stopped, found again.

Like the rest of the repository, this is built and tested in GitHub Actions only.
