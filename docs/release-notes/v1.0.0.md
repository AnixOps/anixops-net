# AnixOps Net v1.0.0

第一个正式版本。

## 升级前请先看

- 内核升到 networkcore 6892161（#265–#268）。
- **证书固定**：订阅里给自签节点写的证书固定（分享链接的 `pinSHA256`、`pcs`，以及各类配置格式里的证书或公钥指纹）
  此前没有生效，“跳过证书验证”的节点实际接受任何证书。现在固定会被校验，但旧版本保存的
  节点里没有固定：
  - 安卓、Linux：升级后自动生效，不需要操作。
  - Windows：启动时自动用保存的订阅内容重新导入当前订阅；其他订阅在订阅列表里会提示“由旧版本导入”，切换到它或更新一次即可。
  - iOS / macOS：会自动更新的订阅打开 App 后会立即更新一次；手动更新或粘贴导入的订阅在订阅列表里会提示，请更新或重新导入。
    单独粘贴的一个节点请重新导入。
- **macOS 旧根证书的信任（仅限曾在 Mac 上“重新生成”或“使用自己的根证书”替换过 HTTPS 解密根证书的用户）**：旧版本替换时
  只删掉了钥匙串里的旧证书，没有撤销“始终信任”，旧根证书仍被系统信任，而且在“钥匙串访问”里看不到。现在替换时会先撤销信任
  （需要登录密码）。之前留下的信任请手动清理：终端运行 `security dump-trust-settings` 查看；有旧证书的 `.cer` 文件时运行
  `security remove-trusted-cert <旧证书.cer>` 删除。

## 修复

- **直连模式真正直连（Windows、Linux、安卓）**：此前“直连”只换了分流规则，经代理的 DNS（包括没有设置 DNS 时隧道内置的
  `1.1.1.1:53`）仍经节点查询，节点不可用时直连模式下整机无法解析域名。现在直连模式下所有连接和 DNS 查询都直接发出；
  与 iOS / macOS 一样，直连模式下“我的规则”不再生效。开启 Fake-IP 时（安卓、Windows TUN，以及 iOS / macOS）还原域名后的
  解析也改为直连。
- **规则集保存在本机（所有平台）**：远程规则集此前每次启动都从空开始，要等下载完成才生效，下载失败时一直不生效。现在每次
  下载成功的列表保存在本机，启动时直接使用，下载失败时继续用上次的列表，满一天后才再下载。
- **证书固定生效（所有平台）**：见上方“升级前请先看”。
- **按网络选择的策略组在 iOS / macOS 生效**：订阅里的 `subnet`（及旧式 `ssid`）策略组此前在 iOS / macOS 上丢了网络条件，
  永远走默认；带 `evaluate-before-use` 的测速组也不再等待首次测速。现在两者都原样交给内核，规则页显示为“按网络选择”。
  旧版本保存的订阅里这类策略组需要重新导入：会自动更新的订阅打开 App 后会立即更新一次，其余在订阅列表里会提示。
- **大节点列表的规则在 iOS / macOS 生效**：超过 64 个节点、没有订阅规则的节点列表此前把全部节点交给内核，被拒后静默改为
  只用选中节点，“我的规则”和局域网直连都不生效，每改一次规则还会断开重连。现在只交选中节点及其前置节点，规则照常生效。
- **超出内核上限时说明原因（iOS / macOS）**：隧道启动前先测量配置大小。插件或调试映射合计超出上限时只关闭 HTTPS 解密，
  请求页说明是体积超限；规则超出时改用选中节点，规则页提示规则没有生效。超过 32 个规则集（含 DNS 规则用到的）时按固定顺序
  去掉最不重要的，并在规则页列出。
- **调试映射计入解密总量（iOS / macOS）**：Map Local 响应体按 Base64 内联在生成的插件里，此前不计入 8 MB 解密总量，
  数量一多整个 HTTPS 解密就被内核拒绝。现在映射生成的插件最多 4 MB，并与已启用的插件共用 8 MB：新增或启用映射、
  加解密域名、导入或启用插件时超出会直接提示；停用、删除和缩小始终可以保存。
- **重定向和 DNS 规则在编辑时校验（iOS / macOS）**：手写的重定向规则按内核语法逐项检查（网段前缀、端口、协议、
  `AND`/`OR`/`NOT` 里的每个条件），DNS 规则合计最多 4096 个域名、后缀和关键词。此前超出或写错时 App 照常保存，
  连接时整份配置被内核拒绝、隧道无法启动。旧版本保存的无效重定向和超出上限的 DNS 规则在连接时跳过，并在对应页面标出。
- **macOS 抓包会话无法保存**：macOS 的隧道是系统扩展，读不到数据保护钥匙串，会话密钥建不起来，手动保存和断开时自动保存都会失败，
  请求页却提示“已加密保存”，断开后抓到的内容丢失。现在 macOS 的会话密钥保存在隧道扩展自己的容器里，只有它能读；断开提示也按
  实际是否能保存来写。
- **更换 HTTPS 解密根证书后隧道仍用旧证书（iOS、macOS）**：重新生成或导入根证书后，已连接并在解密的隧道自动重连改用新证书；
  macOS 由系统发起的连接（自动重连、系统设置的 VPN 开关）不再用上次留下的旧证书签发，App 会带新证书重新连接一次。

## 已知问题

- **iOS / macOS 的隧道配置上限是 64 KB**：节点、规则、已启用的插件和调试映射要一起放进 64 KB 的隧道配置，App 里显示的
  8 MB 插件总量和 4 MB 映射上限在本版本实际用不到。一个常见的去广告插件（约 70–450 KB）、一条超过约 46 KB 的 Map Local
  响应体，都会让 HTTPS 解密在连接时被关闭；订阅里内联规则超过约 1,500 条时规则不生效，只用选中的节点。插件页和映射页
  在超出时会提前提示，连接后请求页和规则页会说明原因，VPN 本身照常连接。放宽这个上限需要内核改动，会在后续版本解决。
  Windows、Linux 和安卓不受影响。
