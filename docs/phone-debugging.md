# 手机连电脑抓包

网络调试客户端计划 D4：手机把 Wi-Fi 代理指向电脑，在电脑上看手机的请求（开了 HTTPS 解密时也能看到解密后的内容）。

## 用法

1. 电脑上的 AnixOps Net 先连接。
2. 打开「扩展」页的「手机抓包」开关，默认端口是 8899。开关下面显示这台电脑的代理用户名和密码（密码默认遮住，可以显示、拷贝和重新生成）。
3. 手机和电脑连同一个 Wi-Fi，用手机相机扫页面上的二维码，打开设置页 `http://<电脑地址>:<端口>/`。
4. 按设置页的步骤操作：
   - 在手机的 Wi-Fi 设置里把代理设为手动，填电脑地址和端口；iPhone 还要打开代理设置里的认证，填电脑上显示的用户名和密码。
     Android 的 Wi-Fi 代理没有用户名和密码栏：浏览器会在第一次访问时弹窗询问，不处理代理认证的其他应用可能连不上，
     这时可以在可信的网络里临时关闭「需要密码」；
   - 安装根证书：iPhone 用描述文件 `/ca.mobileconfig`，装好后还要在“证书信任设置”里打开信任；Android 用 `/ca.crt`。
5. 在手机上打开 `http://cert.anixops/`，页面显示“代理已生效”就说明设置成功。手机的连接会出现在活动页（macOS 上是请求页），进程名显示为 `LAN <手机地址>`。

## 安全边界

- **默认需要用户名和密码**。第一次打开「手机抓包」页面时，客户端用系统的安全随机数生成用户名（`anx-` 加 6 个字符）和
  20 个字符的密码（只用小写字母和数字，去掉了容易看错的 `0 o 1 l i`），保存在系统密钥库里：macOS 是钥匙串，Windows 用
  Windows 数据保护（DPAPI）加密后保存在 `%LOCALAPPDATA%\AnixOps Net\lan-share-auth.dpapi`，Linux 是 Secret Service
  （GNOME Keyring、KWallet），没有时是只有当前用户能读的 `lan-share-auth.json`。每次开启共享时，客户端（Windows、Linux 由
  后端，而不是窗口）把它们交给内核，HTTP 和 SOCKS5 代理请求都要带上，否则内核拒绝。读不出来的凭据会换成新的，共享不会因为
  钥匙串或密钥库出错而改成不要密码。
- 「需要密码」可以关闭，关闭时会提示：同一网络里的任何设备都能通过这台电脑和你的节点上网，它们的请求也会进入抓包。
  只在可信的网络里关闭。公共 Wi-Fi、办公网、宿舍网、运营商级 NAT（100.64/10）和虚拟组网（mesh VPN）都算“局域网”。
- 「重新生成」后，正在运行的共享会用新密码重新开启，已经设置过的手机要重新填写。升级前开过共享的用户，在升级后第一次打开
  这个页面或开启共享时自动生成凭据，默认需要密码。
- HTTP 代理认证（Basic）在 Wi-Fi 上是明文传输的，同网段能抓包的人仍可能看到密码；它防的是随手扫描和蹭用，不能替代可信的网络。
- 设置页（`http://<电脑地址>:<端口>/` 和 `http://cert.anixops/`）按设计不需要密码，所以页面上不显示用户名和密码，只在电脑上显示。
- 只接受回环、私有网段（RFC 1918、100.64/10）、链路本地和 IPv6 ULA 地址的连接，公网来源会被直接关闭。
- 设置页只提供根证书，不提供私钥。证书页和桌面都会显示 SHA-256 指纹，两边一致才安装。
- 断开连接或退出客户端时，共享也随之关闭。

## 根证书

默认每台电脑生成自己的根证书（计划 F2）。Windows 和 Linux 可以在「扩展」页的「自定义根证书」里换成团队已有的 CA，需要 PEM 格式的证书和 PKCS#8 私钥（`BEGIN PRIVATE KEY`）。换完后，手机和其他设备上的根证书都要重新安装。macOS 暂时还不能导入自有 CA，仍使用钥匙串里生成的根证书。

内核接口见 networkcore 的 `crates/engine-embedded/src/lan_share.rs`，包括控制命令 `lan_share`、`start_lan_share` 和 `stop_lan_share`。
