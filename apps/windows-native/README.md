# AnixOps Net for Windows (native)

The Windows client written with WinUI 3 and C# (`docs/architecture/desktop-native.md`). It runs without
administrator rights and talks to the system service `AnixOpsNetCore` (`apps/windows-service`) over a named
pipe.

- `src/AnixOps.Net.Ipc`: the window's end of the channel to the service. The wire format is fixed by the
  samples in `crates/client-ipc/fixtures`, which the tests here read too.
- `src/AnixOps.Net.Session`: what the service asks the signed-in user's side to do (`session.*`: the user's
  system proxy, start after login, notices), and `CoreLink`, the window's standing connection to the
  service. Requests and answers are fixed by the samples in
  `crates/client-service/fixtures`.
- `src/AnixOps.Net.Presentation`: what the app shows and how it is started, without any window (sections,
  wording, launch options, and `Overview`, `Proxies`, `Subscriptions` and `Groups`: the core's `overview`,
  `proxies`, `subscriptions` and `groups` answers turned into those pages' sentences, numbers and rows,
  written the same way as in the Linux window).
- `src/AnixOps.Net.App`: the app. Its title bar, sidebar and pages. `Pages/OverviewPage` asks the core once
  a second and its button connects and disconnects; `Pages/ProxiesPage` imports a subscription or share
  links, lists the nodes under their subscriptions, searches them, tests their delay, and uses the node
  whose row is selected. Its "Subscriptions" button opens `Pages/SubscriptionsDialog`: one row per
  subscription with its node count, last update, use and expiry, where a subscription is updated, renamed or
  removed. A rename or a removal is asked about inside that dialog, since Windows shows one dialog at a time.
  Its "Policy groups" button, which is only there when the subscription in use has groups, opens
  `Pages/GroupsDialog`: one row per group, and the members of a group the user chooses in, where the
  selected member is the one in use.
  `Theme/BrandTokens.xaml` is generated by
  `.github/scripts/design_tokens.py` and never edited by hand.
- `tests/`: unit tests, and `AnixOps.Net.App.UiTests`, which starts the built app and drives it through UI
  Automation. All run in the "Windows native app" job in CI, which also uploads a picture of every page.

Options for tests and screenshots: `--language zh|zh-Hant|en`, `--theme light|dark`, `--page <id>`.
`--pipe <name>` makes the window talk to a service on another pipe than the installed one's.

The tests against the real service need `ANIXOPS_NET_SERVICE_EXE` (the built `anixops-net-service.exe`); CI
builds it. They run it with `--console` on a pipe and a data folder of their own.

Like the rest of the repository, this is built and tested in GitHub Actions only.

The installer is `installer/windows-native` (service registration, upgrade and removal).
