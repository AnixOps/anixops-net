# 客户端会发出哪些连接

AnixOps Net 各平台客户端（iOS、macOS、Android、Windows、Linux，开源版和 ANX 版）自己会发出的全部网络连接。
本文以源码为准；CI 的 “Outbound addresses are documented” 步骤（`.github/scripts/outbound_hosts.py`）要求源码里写死的
每个地址都在本文有对应的小节，新增一个更新服务器、统计地址或查询服务而不写进本文，CI 就不通过。运行时由订阅链接拼出、
客户端会主动发送内容的地址（目前只有“连接质量报告”）登记在脚本的 `RUNTIME` 表里，拼地址的源码带
`network-behavior: <小节>` 标记，标记、登记和本文的小节缺一个，CI 同样不通过。

## 结论

- **装好、打开、什么都不配置：不发出任何连接。** 没有订阅、节点时，客户端只显示导入引导。
- **配置了订阅或节点、但没有连接：不会自己发出连接**，只有到期的订阅更新（见下文“订阅更新”）。测速、查出口地址都要用户
  点按钮才发。
- 没有任何统计、遥测、广告或第三方错误上报 SDK（没有 Firebase、Sentry、Crashlytics 等），没有远程配置，没有推荐服务商
  或推广内容，不查询你的公网地址再上报。
- 不向任何地方发送设备硬件编号、手机型号、安装编号或广告标识。
- 首次启动的用户协议接受之前，界面不加载任何会发出连接的页面。
- ANX 版多了 ANX 出站协议本身；另外 iOS、macOS 有一项**默认关闭**的“向订阅服务商报告连接质量”（见下文“连接质量报告”），
  只有你在设置里打开后才发。除此之外不增加任何别的连接。

下面逐项说明每个连接什么时候发、发往哪里、走哪条路、带什么。“直连”指从你自己的网络直接发出，对方和沿途网络能看到你的
真实地址；“经代理”指通过你选的节点发出。

## 订阅更新

- **什么时候**：你添加订阅时；之后按订阅的更新间隔（App 打开时检查是否到期），或你手动更新时。
- **发往**：你填的订阅地址，没有别的。
- **带什么**：`User-Agent: AnixOpsNet/<版本>`（面板据此返回对应格式）。只有在某个订阅服务器的响应里声明了 ANX 授权
  （`X-AnixOps-Anx-License-Ca`）之后，发往**这个服务器**的请求才带 `X-AnixOps-Device: ed25519:<设备公钥>`，用于签发
  ANX 授权；其他订阅服务器永远收不到这个头。每个订阅服务器各用一把设备密钥，两个面板拿到的公钥不同，无法据此认出是同一
  台设备（anx 规格 §2.4.1）。
- **走哪条路**：未连接时直连，订阅域名的 DNS 查询由系统解析器完成（通常是明文）。这和所有代理客户端一样：连接之前没有
  别的路可走。

## 节点延迟测试

- **什么时候**：你点“测速”、“全部测速”或“重新测试”时。桌面版（Windows、Linux）的概览在**已连接**时会自动测一次当前节点。
- **发往**：先连到你的节点服务器（节点域名的 DNS 查询走系统解析器），再经节点请求
  `www.gstatic.com/generate_204`；桌面概览另外经节点请求 `www.google.com`、`www.youtube.com`、`cp.cloudflare.com` 的
  `/generate_204`。
- **带什么**：一个空的 HTTP 请求，不带任何标识。
- 订阅里 url-test / fallback 组的健康检查（默认 `www.gstatic.com/generate_204`）只在连接后由内核按订阅的设置发出。

## 节点体检

- **什么时候**：只在你对某个节点点“节点体检”时。不会自动运行，也不会在后台定时运行。
- **发往**：先连到你的节点服务器，再经节点做几轮：与 `1.1.1.1`（HTTPS）建连并完成 TLS 握手，请求
  `www.gstatic.com/generate_204` 测请求延迟和抖动。勾选“测下载速度”时，另外经节点从 `speed.cloudflare.com/__down`
  下载一段时间（默认 8 秒、4 条连接，各客户端固定上限 200 MB），下载期间继续请求 `generate_204` 测负载下的延迟。
  iOS、macOS 在 App 里直接经节点发出，不经过隧道；Windows、Linux、Android 由客户端内核经节点发出。“测下载速度”默认关闭。
- **带什么**：空的 HTTP 请求，不带任何标识；结果只显示在界面上，不保存、不上传。
- 下载会消耗节点流量（最多 200 MB）；按流量计费的节点请只测延迟。

## 出口地址

- **什么时候**：iOS、macOS 在你点概览的出口地址卡片查询时；Android 每次连上后一次；桌面版连上后、换节点或换模式后各一次。
  未连接时不查。
- **发往**：经代理请求 `https://www.cloudflare.com/cdn-cgi/trace`，响应里的 `ip=` 和 `loc=` 就是网站看到的出口地址和
  地区，只显示在界面上，不保存、不上传。Cloudflare 看到的是节点的地址，不是你的真实地址。

## 连接质量报告

- **什么时候**：只有你在 iOS、macOS 的“设置 › 隐私”打开“向订阅服务商报告连接质量”之后，**默认关闭**。打开后，App
  在前台显示概览（macOS 为概览页或仪表盘窗口）并且已连接时，约每小时发一次（每次间隔 50–70 分钟随机）。Android 和
  桌面版没有这项上报。只报 ANX 协议的节点，所以开源版（没有 ANX 节点）打开了也不会发；ANX 版只在当前配置里有来自
  订阅的 ANX 节点时才发。
- **发往**：提供这些节点的订阅服务商的面板，地址由订阅链接拼出：去掉查询参数、片段和最后一段的扩展名，再加
  `/report`，例如 `https://panel.example.com/s/abc123.yaml?flag=x` 发往 `https://panel.example.com/s/abc123/report`。
  订阅链接里的令牌随路径发出，服务商能据此对应到你的账号。每个订阅只收到自己节点的数据，其他服务商收不到。
- **走哪条路**：由 App 用系统网络接口（`URLSession`）发出，和 App 自己的其他请求一样由系统决定路由：隧道接管默认路由
  时会进入隧道，再按你的规则直连或经代理。
- **带什么**：一个 `POST` 的 JSON，带系统默认的 User-Agent：`client`（`anixops-net/<版本>`）、`platform`（`ios` 或
  `macos`）、`network`（`wifi`、`cellular`、`ethernet` 或 `other`）、`window_secs`（本次统计覆盖的秒数），以及 `nodes`：
  每个节点的名称（`node`）、服务器地址和端口（`server`）、协议（`proto`）、上次上报以来的成功和各类失败次数
  （`ok`、`fallback`、`timeout`、`refused`、`reset`、`after_handshake`、`keepalive_lost`、`other`）、是否因连续被拒而
  暂停（`stopped`）和与服务器的时间偏差（`clock_skew_secs`）。只有计数，不含你访问的网址、域名或目标地址。
- **关闭和重新打开**：关闭时删除本机保存的计数基线和上次上报时间。重新打开时以那一刻的计数为起点，关闭期间的计数不会
  补报。从没有这个开关的旧版本升级后，开关为关闭，旧版本留下的计数基线会被删除。
- 节点因连续被拒而暂停时，App 在本机提示你（可以恢复或更新订阅）；这个提示不发出任何连接，开关关闭时照常显示。

## 国内直连延迟

- **什么时候**：Android 和桌面版连上后一次；桌面版换节点、换模式或点“重新测试”时。未连接时不测（桌面版在未连接时
  只有点“重新测试”才测）。
- **发往**：直连发一个 `HEAD https://www.baidu.com/`，只计时，不读内容。百度能看到你的真实地址，和你用浏览器打开
  百度首页一样；不带任何标识。

## GEOSITE,cn 与 GEOIP,CN 列表

- **什么时候**：只有你导入或自己写的规则里用到 `GEOSITE,cn` 或 `GEOIP,CN`、而订阅没有自带同名规则集时，内核在连接后
  下载，一天最多一次（docs/no-presets.md）。下载成功的列表由内核保存在本机 App 自己的数据目录（`rule-sets` 文件夹，
  文件名是地址的摘要，不含地址本身），下次启动直接使用，满一天后才再下载；下载失败时继续用上次的列表。没有保存过的
  列表在连接后立即下载。你自己按地址添加的规则集和订阅自带的规则集也是这样。
- **发往**：直连 `raw.githubusercontent.com` 上的两份公开列表（gaoyifan/china-operator-ip、Loyalsoldier/v2ray-rules-dat）。
  不带任何标识。

## 连接后的 DNS

- 只在连接后由内核发出，服务器是你选的：默认“系统 DNS”用本机网络的解析器；“加密 DNS”是经代理的 Cloudflare DoH
  （`1.1.1.1`）。设置里的一键选项（阿里 `223.5.5.5`、腾讯 DNSPod `1.12.12.12`、Cloudflare `1.1.1.1`、Google `8.8.8.8` /
  `dns.google`、Quad9 `9.9.9.9`，自定义 DNS 示例里的 `dns.adguard-dns.com`）只是服务器地址，选了才用。
- 规则选中“直连”或“拒绝”不会让设为“经代理”的 DNS 服务器改走直连（内核 docs/architecture/embedded-dns.md
  “DNS 泄露核对”）。
- “直连”模式下内核不看任何规则：所有连接和所有 DNS 查询（包括设为“经代理”的服务器，以及没有设置 DNS 时隧道内置的
  `1.1.1.1:53`）都从你自己的网络直接发出，不经任何节点（内核 docs/architecture/embedded-dns.md
  “直连模式不经节点”）。五个平台相同。

## macOS 软件更新

- 只有构建时配置了更新地址（`AnixOpsUpdateFeedURL`）的 macOS 版本才检查更新；**目前发布的版本都没有配置，不检查**。
  启用后也**默认不自动检查**：只有你点“检查更新”，或在“设置 › 软件更新”打开自动检查（之后每天最多一次）时，才请求签名的
  更新信息，只带 `Accept: application/json` 和系统默认的 User-Agent。其他平台没有应用内更新检查。

## 崩溃报告

- 崩溃报告只保存在本机（去掉了地址、域名、密钥等敏感内容），由你自己决定是否导出发送。只有构建时配置了上传地址
  （`ANIXOPS_CRASH_REPORT_URL`）的版本才会上传，**目前发布的版本都没有配置**（docs/architecture/client-health.md）。
- `/metrics` 只监听本机 `127.0.0.1`，默认关闭。

## 只在用户点开时打开的链接

- 用户协议、隐私政策等页面里的 `github.com` 链接，只有你点了才由系统浏览器打开，App 自己不请求。

## 用户自己的配置

订阅、节点、规则、规则集、插件和脚本里写的地址是你自己带来的数据：插件脚本可以按你装的插件发请求，规则集按你填的地址
下载。这些不在本文范围内，客户端不会自己添加。

## 系统本身的连接

操作系统和系统组件自己的连接不归 App 控制，例如 iOS / macOS 的 App Store、证书校验，Windows 的 WebView2 组件更新。
桌面版界面运行在 WebView2 / WebKitGTK 里，CSP 只允许加载 App 自带的文件，禁止任何外部资源；Windows 版关闭了
WebView2 的 SmartScreen 检查。

## 自己验证

1. 新装客户端，不导入任何配置，打开放几分钟：抓包应当看不到任何来自客户端的连接。
2. 导入订阅（会看到一次订阅请求），不连接，切到各个页面放几分钟：除到期的订阅更新外不应有连接。
3. 连接后：按上面的列表核对每一条。默认设置下看不到发往订阅链接 `/report` 的请求；在 iOS、macOS 打开“向订阅服务商
   报告连接质量”并停在概览约一小时后，才会看到一条（只在用 ANX 节点时）。

Android 可以用 PCAPdroid 按应用抓包；iPhone 可以用 `rvictl` 把手机接到 Mac 上抓整台手机；桌面可以用 Wireshark。
发现与本文不符的连接，请提 issue。
